HAMLOG / เชื่อมโยง

Windows HAMLOG Ver5.48 ใช้ API ตั้งแต่5.27c เปิด HAMLOG ตัวเดียวพร้อมช่อง QSO และสิทธิ์เดียวกัน เชื่อมโยง → HAMLOG ทดสอบแสดงชื่อหน้าต่างตอบ การส่งเริ่ม OFF ค่าเริ่มกรอกอย่างเดียว เลือกขอบันทึกได้ ใช้ร่วมทุกโปรไฟล์ ส่งหลัง ADIF สำเร็จ แบบเอง/TU73 เหมือนกัน เลขเพิ่มครั้งเดียว CALL เวลา JST RST ทั้งคู่ ความถี่ RTTY; SENT/RCVD ใน Remarks1 และ CALL สถานี Remarks2 ไม่เดา JCC/JCG จาก exchange คง QSL/Code/GL/Name/QTH ของ HAMLOG

แบบกรอกอย่างเดียวต้องบันทึกใน HAMLOG ก่อน QSO ถัดไป ไม่ทับร่างอื่น แบบอัตโนมัติตรวจช่องก่อน Save หากล้มเหลว ADIF บันทึกแล้ว ให้ตรวจ HAMLOG อย่าเพิ่ม QSO ซ้ำ

Hamlib 4.7.2 ไม่รองรับควบคุมแบนด์วิดท์รับรุ่นนี้ ใช้ปุ่มวิทยุ

ส่งความถี่ไป HAMLOG โดยตัดทศนิยม MHz เหลือ 3 ตำแหน่ง (21.07982 → 21.079) ADIF ของ PSRTTY คงความละเอียดเดิม

zLog: เชื่อม Z-Server แบบทันที

ในการตั้งค่า HAMLOG ให้เปิดรูปแบบ 599 และตรวจว่าช่องตั้งค่ามี RTTY=5*9 แม้จะมี RTTY อยู่แล้วก็ตาม

ลำดับคือ CALL → ประมวลผล Enter → ใส่ข้อมูล QSO นี้ → ตรวจสอบ → Save โดยตั้งวันที่ เวลา และ RST หลัง Enter หากเลือกส่งเข้าเฉพาะช่องกรอก ต้องกด Save เอง เมื่อค่าไม่ตรงกันจะแสดงช่อง ค่าที่ส่ง และค่าที่อ่านกลับ แล้วหยุดการบันทึกอัตโนมัติ

  1. เปิด Z-Server แบบ TCP ปกติและเชื่อม zLog ตรวจการแข่งขัน CALL สถานี exchange และเวลา
  2. เปิดเมนูเชื่อมโยง → zLog ตั้งเซิร์ฟเวอร์ พอร์ต ชื่อเครื่องไม่ซ้ำ ผู้ปฏิบัติการและ TX PC เดียวใช้ 127.0.0.1 ตั้ง UTC/JST และทศนิยมตรงกับ zLog
  3. เปิดส่ง QSO ใหม่ แล้วบันทึกและเชื่อมต่อ ค่าเริ่มปิด

บันทึกเองหรืออัตโนมัติ TU73 ส่งหลัง ADIF สำเร็จ: CALL เวลา RST exchange ส่ง/รับ RTTY ย่านและความถี่ exchange รัฐ CQ WW ส่งครบ แต่ตรวจการตีความและตัวคูณใน zLog

เก็บ QSO ไม่ยืนยันที่ var/zserver-outbox.json ตรวจ ID/ข้อมูลเมื่อเชื่อมใหม่ ไม่ส่ง log เก่าหรือ QSO ขณะปิดเชื่อมโยงอัตโนมัติ ใช้ ADIF ส่งรวมได้ อย่าบันทึก QSO เดียวสองทาง ยืนยันเซิร์ฟเวอร์แล้วต้องตรวจ log zLog ด้วย ไม่รองรับ TLS/ล็อกอินและซิงค์การแก้ไข/ลบกลับ

ADIF UDP

ใน Log4OM2 เปิด UDP Inbound แบบ ADIF MESSAGE และใช้พอร์ตเดียวกัน ตัวอย่างเริ่ม 127.0.0.1 (PC เดียวกัน) พอร์ต 2236 ปรับตามตัวรับ

ส่ง QSO ใหม่ครั้งเดียว ไม่ส่งการแก้ไข ลบ หรือบันทึกเก่า UDP ยืนยันการรับ/บันทึกไม่ได้ ไม่ส่งซ้ำอัตโนมัติ หากส่งล้มเหลวยังคงบันทึก PSRTTY

หากไม่มีความถี่ก่อนบันทึก จะแสดงคอลไซน์คู่สถานีและขอค่า MHz เช่น 7.045, 14.085, 50.303 ค่านี้ใช้เป็น FREQ ของ QSO นี้และระบุ BAND จากตารางแบนด์ที่รองรับ หลังบันทึก HAMLOG, ADIF UDP และการเชื่อมต่ออื่นจะใช้ค่าเดียวกัน หากยกเลิกจะไม่บันทึกหรือส่งต่อ ใช้กับ TU73 ด้วย
