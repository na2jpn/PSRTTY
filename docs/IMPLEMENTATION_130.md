# 1.30 実装メモ

基準：PSRTTY_1.29_FULL_SOURCE.zip。送信・通常の音声デコード・ログ連携の変更はありません。

## IQデータ経路

ExtIOネイティブコールバックは有限の原データコピーのみ実施。サンプル形式変換と
パイプ出力は専用スレッドへ移し、連続データを最大約32kサンプル／待ち20msで集約します。
ブリッジの待ち行列は約0.5秒のサンプル数で制限します。満杯時もサンプル位置を進め、
後続のRYIQヘッダーからPython側で失われたサンプル数を計算できます。
ブロック位置・レート・中心の不連続は集約を分けます。標準16/24/float等の変換とIQ反転を保持。

Python側は固定8ブロックを廃止し、合計信号時間0.5秒、最大4096ブロックで制限します。
約20ms単位でデコードへ渡します。異なる中心・レートや欠落境界をまたいで結合しません。
ローカル満杯は捨てたサンプル数を記録し、後続の最初の受理ブロックにリセットを付けます。
前段FIRはfactor>=16・4096サンプル以上の入力にFFT畳み込みを使用し、その他は既存のupfirdnを使用。
位相・過去サンプルを保持するため、経路を途中で切り替えても境界を連続に保ちます。

## 周波数

ICOM初期ON、RTL初期OFFのfollowをui.ry_skimmer_inputs[method]へ保存します。
周波数連動とWクリック時のモード連動は別設定です。メイン接続時のみ追従します。
ExtIOへ標準入力でCENTER <Hz>を送り、DLL操作はメッセージ処理を行うSTA側で実施。
SetHWLOで要求し、GetHWLOを読み取ります。初回開始にもSetHWLOを使用し、ストリーム開始後にも適用します。
実際のIQ中心をデータヘッダーに載せ、目盛り・検出周波数は常にその値で計算します。
読み取りは変更通知と500msポーリングで更新。DLLが要求に応じない場合は、2秒後から
指定・実際のMHzを赤字で表示し、値が変わった時に診断ログを記録します。
ICOM送信中の中心変更要求は保留し、RXへ戻ってから実行します。
機器側で独立受信できる範囲はメーカーDLL／機種の動作に従います。
ExtIO API参照： https://www.hdsdr.de/download/LC_ExtIO_Types.h

RTL-SDRも専用制御スレッドで中心を設定・読み取りし、再同調時はDSPをリセットします。

## 受信状況と診断

IQ受信状況と復号文をタブで切り替えます。前者は250msの観測ごとに直近10秒の内訳を更新。
水色＝処理済み、橙＝入力に対して増えた処理待ち、赤＝欠落、灰＝IQ未着。
縦軸は観測区間の内訳の割合です。RF強度、RTTY検出数、デコード成功率ではありません。
ブロックが到着・処理されるタイミングにより、短い処理待ちが表示される場合があります。
欠落率はサンプル時間に基づく直近10秒の値。処理待ちは現在の待ち行列の信号時間です。
入力レートは観測区間に実際に受け取ったサンプル数／経過秒で、設定値の単純表示ではありません。
ブリッジより手前のUSB機器内部の欠落は、DLLから通知がない場合は検出できません。

var/diagnostics/ry_skimmer.logに10秒ごとの受信／処理／欠落数、待ち時間、レート、
実際のIQ中心を記録。ブリッジもコールバック数・欠落・キュー数を記録します。
既存の500kB・最大3世代の診断ログ保持設定を使用し、無制限に増やしません。

## マクロ

JARLコンテスト 1は利用者指定のF1～F9の文面そのままです。
F4ラベルはTU 73ですが、文面はTU QRZ DE {MYCALL} CQで、73は補いません。
送信文のTU 73による自動ログ判定は従来どおりで、この文面では自動ログの条件に該当しません。
従来のテンプレートをJARLコンテスト 2と表示。旧保存名は編集画面で2に対応付け、
保存済みのマクロ自体は変更せず、明示的な反映時のみテンプレートを適用します。
CQ WW等の他テンプレート内容は保持しています。

## ビルド

同梱32/64bit ExtIOブリッジも新ソースから再構築済みです。
Windowsビルドは従来どおり.NET Framework cscで両方再構築・自己検査します。
完成したEXEの検査に、実時間の1.92 MS/s・512単位の非同期入力検査を追加。
通常の2局模擬IQ復号検査と両方成功してから配布ZIPを作成します。
