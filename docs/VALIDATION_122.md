# Ver1.22 検証 — 2026-10-16

## 全体回帰テスト

Python 3.12、PySide6、pyserial、PortAudioを用い、Qtはoffscreenで実行しました。

`python3 -m unittest discover -s tests -v`

- 928件、236.672秒、失敗0、スキップ1。
- スキップは既存のローカルソケット作成をOSが拒否するIPCテストです。Windows実機確認対象です。
- 実行ログは `OK (skipped=1)` まで出力されています。

全体テスト開始後に、設定画面の外部接続PTTテストから保持中のFSK用COMを借用する処理と、接続初期化失敗時に元のエラーを保持する後始末を追加しました。この部分は下記の最終確認で検証しています。全体テスト928件が、最後に追加したテストをすべて含むという意味ではありません。

## 最終確認

`python3 -m unittest tests.test_v122 tests.test_v117 -v`

- 51件、8.346秒、失敗0、スキップ0。
- Ver1.22専用テスト19件と、外部PTT・設定画面などの既存関連テストを含みます。
- 接続時にFSK用COMを開き、複数回の送信でも開閉しないこと。
- モード確認に失敗した場合、未準備のCOMを開かずPTT ON/OFFとも呼ばないこと。
- COM初期化で模擬的に一時送信状態が生じても、RXが確認されるまで正式なPTT開始をしないこと。
- 初期化後にTX状態または状態不明が続く場合に停止し、強制PTT OFFやキーイングを行わないこと。
- STOP後の再送、PTT開始失敗時の解除、ポート／キーライン変更、Profileのコントローラー切替、切断・抜線時の解放。
- FSK用COMと外部PTTの別ライン共用、設定画面の外部PTTテストでの借用、競合するキーライン・極性の拒否。
- ICOMのCAT共用COMをFSKが閉じないことと、AFSK接続でFSK用COMを開かないこと。
- 8言語のエラー段階表示。

先行の集中テストでは、既存の共有PTTテストの模擬コントローラーが受信状態を返さないため1件失敗しました。新たに必要となるRX確認に合わせて、模擬コントローラーに明示的な受信応答を設定し、関連テストと上記全体テストで通過を確認しました。モード確認失敗時にCOMを開かず、未開始のPTTを解除しないという新仕様に合わせ、旧テストのリソース・コール回数の期待値も更新しています。
