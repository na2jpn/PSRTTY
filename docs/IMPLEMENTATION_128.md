# PSRTTY 1.28 — 2026-10-22

## RYスキマー

入力設定のスタートでDLLの存在・PE形式・32/64bit・対応する起動用EXEを検査し、保存成功後は設定を閉じてスキマーを前面に表示し、受信開始を予約する。検査・保存に失敗したときは設定画面を残して赤字で原因を示す。保存失敗時は入力設定のメモリー内変更を戻す。

メイン側では同期例外、バックグラウンド開始エラー、ネイティブ側エラー、IQ入力タイムアウトを赤字で保持し、次のスタートまで通常ステータスで上書きしない。開始処理完了だけでは「受信中」にせず、最初のIQデータ処理を確認する。15秒間データが届かなければ入力・DSPを停止して再試行可能にする。

ExtIOブリッジはDLL読込み、InitHW、OpenHW、StartHW、受信開始の段階と例外を標準エラーに出力。Python側は標準エラーを独立スレッドで排出し、パイプ詰まりを防止しながら末尾24件を保持する。DLLの32/64bitに合う別プロセスを使い、メインの音声入力とは独立する。

IC-7610のIQのみの受信はUSB 2のケーブル1本。現在のPSRTTYの通常CAT・USB Audioも併用する場合はUSB 1も接続する。USB 2を利用する他ソフトによる無線機制御の可否と、現在のPSRTTYのCAT経路は区別する。USBハブが今回の不具合原因だと断定する根拠はない。

今回の実機報告の根本原因は特定できていない。起動時に見逃されていた例外・状態を可視化して診断可能にする変更であり、実機で直ったとする報告ではない。

## Wクリック時モード連動

RYスキマー・RYレーダーのJA-BAND ONLYの横に共通チェックを配置。初期ON、ui.ry_mode_linkへ保存し、両ウィンドウに反映。OFFは周波数のみ。ONは現在のProfileのAFSK data_mode、またはFSK modeを使う。既存のCATキュー・送信中の操作制限・排他処理を共用し、PTTや送信開始は行わない。

ICOMはCI-V 26でフィルター欄を省略し、結果を読み戻す。26を拒否する旧機種は06でモードを変更し、DATAコマンドが要求するフィルター欄には無線機が選んだ値を読み戻して反映する。固定のFIL1等は指定しない。Hamlibは既存のモード設定の帯域幅維持処理を使用する。モード変更に伴い無線機自身が変更するフィルター動作までは保証しない。

## 診断ログ

保存先：var/diagnostics/。UTC日時付きUTF-8。以下の11種類を必要になったときに作成する。

|ファイル|対象|
|---|---|
|app.log|起動・終了、未処理例外、共通バックグラウンド例外|
|radio.log|CI-V/CAT/Hamlib接続・切断・設定操作、周波数取得失敗・回復|
|audio.log|音声入力開始・停止・エラー|
|tx.log|AFSK/FSK開始・終了・PTT・キーイング開始段階・エラー|
|decode.log|メイン／サブデコードの設定・有効状態・開始停止|
|ry_skimmer.log|入力設定・DLL・起動用EXE・ネイティブ各段階・IQ／DSPエラー|
|ry_radar.log|接続先・巡回・状態・通信エラー|
|integration.log|HAMLOG／Z-Server／ADIF UDPの結果・エラー|
|printer.log|RTTYプリンター設定・接続・停止・異常理由|
|settings.log|設定保存・言語ファイル・クラブデータの読込みと移行|
|update.log|更新・再起動・バックアップ|

各種類は現行.logと.log.1/.log.2の最大3ファイル。500,000バイトを超える書込み前に世代交代。全体12,000,000バイトを超えたら古い過去世代から整理する。ただし、各種類の最後に存在する1ファイルは必ず残す。この規則は全体上限より優先する。診断の保存が失敗しても本来の操作は妨げない。

毎サンプル・毎文字・通常の周波数ポーリング値は保存しない。QSOのADIF、送受信テキスト、実バックアップはこの管理対象に含めず、自動削除しない。旧版が作ったvar/language.logなどは遡って削除しない。

## 配布・クラブデータ

Windows配布ZIPのルートはpsrtty.exeとフォルダーだけ。更新マニフェストでも1.28以降の余分なルートファイルを拒否する。開発用フルソースZIPのビルドスクリプト・仕様書は対象外。

外部CSVとメタデータはconfig/club_db.csv、config/club_db_meta.json。旧ルートのファイルを一時ファイルへコピー・照合・置換・再照合してから旧ファイルを削除する。既存config側に違う内容があればハッシュ付きpre-128ファイルを残し、旧版で有効だったルートのデータを引き継ぐ。失敗時は元ファイルを残す。デフォルトはEXE内の組込みデータから作成するため、以後の配布ファイルでユーザーの編集を上書きしない。

使用しないQt WebEngine/QML/Quick、tkinterをPyInstallerの対象から除外。IQ処理に使うSciPyおよび関連モジュールは保持。unittestもSciPy→NumPyの実行時依存を確認したため保持。Windowsでの削減量は未測定。

## 更新用保存領域の整理（正本への追加）

正常に起動したWindows EXEが、画面表示後にバックグラウンドで整理を行う。
`var/updates`は最新1世代を`update_<世代ID>.zip`の1ファイル、`var/backups`は最新2世代を`backup_<世代ID>.zip`の2ファイルとして保持する。
1.28より前のフォルダー形式にも適用し、古い世代から上限超過分を削除する。保持対象のZIP化・CRC検査・サイズおよび変更検査が終わるまで元フォルダーは削除しない。

更新ZIP検査・コピー中はプロセス間ロックを取り、準備完了後は親プロセスのPIDと生成時刻を記録して、更新待ちの作業フォルダーを保護する。PIDが再利用された場合は生成時刻で区別する。更新ヘルパーは再起動確認が終わるまでロックを保持し、本体の整理は競合時に待ち直す。旧版ヘルパーもWindowsのプロセス一覧と実行イメージのフルパス照合から保護する。

保持する更新ZIPには元のrelease.zipと結果等の記録を含める。重複したpayload展開物と使い終わった更新用EXEは含めない。バックアップではlogdata/backupsやvar/updates、var/backupsを入れ子にしない。今後の更新前スナップショット作成時も同じ重複を除外する。

通常のconfig、logdata内のADIF・送受信文は削除対象ではない。logdata/backupsは後述のログバックアップ保持規則で別途整理する。診断ログの500kB・3世代・全体12MB規則とも別管理である。更新作業が成功しなかった場合はその場で整理せず、その後の正常起動時に整理する。

保存場所に不明なファイル、リンク／ジャンクション、不正なZIPなどがあった場合や、ディスク容量・権限で整理できない場合は削除を進めず、診断ログと画面のステータスに原因を示す。その場合は上限まで整理できないことがある。動作中の更新も一時的な上限超過を許容する。

【ログバックアップの保存数整理】
logdata/backups: PSRTTY_logs_*.zip は最新3個、YYYYMM.adi.*.bak は月別ADIFごとに最新3個。
正常起動後に既存分を整理。終了時・QSO件数ごと・手動の作成設定はそのまま使い、成功後に整理。
ADIF編集・削除成功後も整理。新しい保持対象が破損していれば古い分を削除しない。
現在のADIF、日別生ログTXT、月移動の復旧フォルダー、不明なファイルは削除しない。
このためbackupsフォルダー全体が必ず3ファイルになる仕様ではない。
