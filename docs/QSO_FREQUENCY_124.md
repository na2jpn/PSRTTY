# Ver1.24 登録前の交信周波数確認

## 対象

「ログに追加」またはTU73などの自動ログ登録時に、今回のQSOに周波数が入らない場合だけ、登録前に入力を求めます。既存の周波数採用ルールは維持します。

- 取得した現在周波数があれば使用します。
- 未接続時に最後に取得した周波数を使う既存の処理は維持します。
- 接続中に新しい周波数が取得できていない場合、以前の取得値を自動採用しない既存の方針を維持し、入力を求めます。
- 「外部接続による手動」では過去のCAT取得値を使わず、交信周波数を入力してもらいます。

## 日本語表示

手入力などにより、交信した周波数が反映されていません。
周波数を指定してください。

相手のコールサイン：JA1ABC

周波数［　　　　　　　　］MHz

例：7.045、14.085、50.303

［キャンセル］［登録］

コールサインは確認用の読取り専用表示です。説明・ラベル・ボタン・エラーは8言語に対応します。

## 入力とFREQ・BAND

- 入力はMHz単位でDecimalを用いてHzの整数へ変換します。小数点と小数コンマ、全角数字・小数点を受け付けます。
- 空欄、0、負数、数値以外、単位文字、指数表記、1 Hz未満の端数は受け付けません。桁数は32文字までです。
- 周波数範囲は既存のQSOログ編集画面と同じ、0 Hzより大きく15 GHz未満です。
- 入力エラーはダイアログ内で表示し、入力欄へ戻します。追加の確認ダイアログは出しません。
- 7.045 MHz→7045000 Hz→40m、14.085 MHz→14085000 Hz→20m、50.303 MHz→50303000 Hz→6mなど、既存のバンド対応表からBANDを求めます。
- この版でバンド対応表を拡張する変更はしていません。対応表の範囲に該当しない周波数では、既存どおりBANDは空になります。周波数から架空のバンドを推定することはしません。
- 手入力した値は今回のQSOにだけ設定し、無線機の現在周波数・最後の取得値や次の交信へ持ち越しません。無線機へ周波数設定コマンドを送ることもありません。

## 登録の順序

1. CALL・日時を既存どおり確認し、登録対象の交信を作成します。
2. 周波数がない場合、CALLを表示してMHzの入力を求めます。
3. キャンセル・ウィンドウを閉じる・アプリ終了の場合、登録せず戻ります。CALL・日時・RST・送受番号は保持します。
4. 入力済みならその値をQSORecord.freq_hzへ反映し、通常のADIF保存へ進みます。
5. ADIF保存成功後に、既存どおり番号繰上げ・一覧更新・バックアップ・外部転送を行います。

外部連携は同じQSOのデータを受け取ります。HAMLOG、zLog/Z-Server、ADIF UDPでそれぞれの既存形式へ変換し、FREQ/BANDは各形式の対応に従います。ADIF UDPの形式そのものは変更していません。

モーダル入力中にQtのイベントループから登録処理が再度呼ばれても、同じQSOを二重登録しないようガードします。TU73自動登録も同じ入口を通るため、同じ確認と取消処理になります。キャンセル後に自動で登録を再試行することはありません。

## JT_Linkerの報告との関係

JT_Linkerで周波数の文字列処理中に例外が出たとの報告を受けています。この版は周波数未取得のQSOをそのまま新規登録・転送する状況を避ける対応です。受信データとJT_Linkerの実装を照合して原因を確定したものではなく、JT_Linker固有のUDP互換性や例外の解消は保証していません。

Ver1.23のHAMLOG Enter処理・照合診断、Hamlibのデバッグ出力抑制、Ver1.22由来のFSK対策は保持します。
