HAMLOG / integrasi

Windows HAMLOG Ver5.48 memakai API sejak5.27c. Jalankan satu HAMLOG dengan input QSO terbuka dan hak akses sama. Integrasi → HAMLOG: uji koneksi menampilkan judul respons. Transfer awal OFF; bawaan isi saja, pilihan minta simpan. Semua profil berbagi. Transfer setelah ADIF sukses, manual/TU73 sama, serial naik sekali. CALL, waktu JST, kedua RST, frekuensi, RTTY; SENT/RCVD di Remarks1, CALL stasiun Remarks2. Jangan tebak JCC/JCG dari exchange; QSL/Code/GL/Name/QTH HAMLOG dipertahankan.

Dalam mode hanya isi, simpan di HAMLOG sebelum QSO berikutnya. Draf lain dilindungi. Simpan otomatis memeriksa isian sebelum Save. Jika gagal, ADIF sudah tersimpan: periksa HAMLOG, jangan tambah QSO lagi.

Hamlib 4.7.2 tidak mendukung kendali lebar pita RX model ini. Gunakan kontrol radio.

Frekuensi ke HAMLOG dipotong hingga 3 angka desimal MHz (21.07982 → 21.079). ADIF PSRTTY tetap menyimpan presisi asli.

zLog: tautan langsung Z-Server

Di pengaturan HAMLOG, aktifkan format 599 dan pastikan isinya mencakup RTTY=5*9, meskipun RTTY sudah terdaftar.

Urutan: CALL → proses Enter → isi QSO ini → verifikasi → Save. Tanggal, waktu, dan RST diisi setelah Enter. Pada mode hanya isi kolom, Save tetap manual. Jika tidak cocok, nama kolom dan kedua nilai ditampilkan; penyimpanan otomatis dihentikan.

  1. Jalankan Z-Server TCP biasa dan hubungkan zLog. Periksa kontes, CALL stasiun, exchange dan waktu.
  2. Buka Integrasi → zLog. Atur server, port, nama klien unik, operator dan TX. Satu PC memakai 127.0.0.1. Samakan UTC/JST dan desimal dengan zLog.
  3. Aktifkan pengiriman QSO baru lalu simpan dan hubungkan. Awalnya OFF.

Catatan manual dan otomatis TU73 mengirim sesudah ADIF tersimpan: CALL, waktu, RST, exchange, RTTY, band dan frekuensi. Exchange negara bagian CQ WW dikirim utuh; periksa penafsiran kontes dan pengali di zLog.

QSO belum terkonfirmasi disimpan di var/zserver-outbox.json. Saat terhubung lagi, ID dan isi diperiksa. Log lama dan QSO saat tautan OFF tidak dikirim otomatis; gunakan ADIF untuk kirim banyak. Jangan catat QSO sama lewat kedua jalur. Konfirmasi server bukan konfirmasi klien zLog; periksa lognya. TLS/login dan sinkron balik sunting/hapus belum didukung.

ADIF UDP

Di Log4OM2 aktifkan UDP Inbound ADIF MESSAGE dengan port sama. Contoh awal: 127.0.0.1 (PC sama), 2236. Sesuaikan dengan penerima.

Kirim tiap QSO baru sekali. Edit, hapus dan log lama tidak dikirim. UDP tidak mengonfirmasi penerimaan/pencatatan; tanpa kirim ulang otomatis. Log PSRTTY tetap saat gagal.

Jika frekuensi belum ada, dialog menampilkan callsign lawan dan meminta MHz (7.045, 14.085, 50.303). Nilai menjadi FREQ QSO ini dan BAND ditentukan dari tabel band yang didukung. HAMLOG, ADIF UDP, dan tautan lain memakai nilai yang sama setelah pencatatan. Batal tidak mencatat atau mengirim. Berlaku juga untuk TU73.
