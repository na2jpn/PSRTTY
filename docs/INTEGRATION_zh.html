HAMLOG 与外部软件

HAMLOG Ver5.48

使用 Windows Turbo HAMLOG/Win 5.27c 起公开 API。只启动一个 HAMLOG 并打开 QSO 输入窗口，两程序权限相同。联动 → HAMLOG 设置，测试后显示响应窗口标题。启用记日志时传送（默认 OFF）。默认仅填输入栏，需自行在 HAMLOG 保存；也可选择传送后请求保存。各配置档共用。PSRTTY 成功保存 ADIF 后，手动与 TU73 都传送，发送序号只增加一次。传 CALL、JST 日期时间、双方 RST、频率、RTTY；SENT／RCVD 放 Remarks1，本台呼号放 Remarks2。不把比赛交换猜为 JCC/JCG，保留 HAMLOG 的 QSL／Code／GL／Name／QTH。

仅填输入栏时，请在下一QSO前于HAMLOG保存。不覆盖其他草稿。自动保存先核对字段再执行Save。失败时PSRTTY ADIF已保存，请检查HAMLOG，不要重复添加QSO。

传送失败

弹窗给原因与处理。PSRTTY ADIF 已保存，请勿重复添加！中断会记操作日志而不自动重试。核对 HAMLOG，只手填缺少 QSO，或 文件 → HAMLOG CSV 导出。HAMLOG 的记录、修改和删除不反向同步。

传给HAMLOG的MHz频率截断至小数点后3位（21.07982 → 21.079）。PSRTTY ADIF保留原始精度。

zLog：Z-Server实时连接

请在HAMLOG设置中启用599格式指定，并确认设置栏包含RTTY=5*9。即使已添加RTTY也请检查。

流程为CALL输入 → Enter处理 → 填写本次交信内容 → 核对 → Save。Enter处理改变的日期、时间和RST等将在之后按本次交信重新设置。仅转入输入栏时须手动Save。不一致时显示项目、发送值和回读值，并停止自动保存。

  1. 启动普通TCP Z-Server并连接zLog。核对比赛、自局CALL、交换号与时间基准。
  2. 打开连接菜单的zLog设置。指定服务器、端口、唯一终端名、操作员及TX编号。同一电脑用127.0.0.1。UTC／JST及小数符号须与zLog一致。
  3. 启用发送新交信并保存连接。默认关闭。

手动及TU73自动记录均在ADIF保存后发送新交信：CALL、时间、RST、收发交换号、RTTY、波段、频率。CQ WW州／省交换号原样发送；请在zLog核对比赛解释及倍数。

未确认交信保存在var/zserver-outbox.json，重连时核对ID与内容。旧日志及连接关闭期间的新交信不会自动发送，可用ADIF批量传送。同一交信不要用两种方式重复注册。服务器确认后仍须检查zLog。不支持TLS／登录及反向编辑、删除同步。

ADIF UDP

在Log4OM2开启UDP Inbound的ADIF MESSAGE，并使用相同端口。初始示例127.0.0.1（同一PC）、2236，请按接收设置调整。

每个新保存QSO发送一次，不发送编辑、删除或旧日志。UDP无法确认接收或登记，不自动重发。发送失败仍保留PSRTTY日志。

登记时若缺少交信频率，对话框显示对方呼号并要求输入MHz频率（例如7.045、14.085、50.303）。输入值用于本次交信的FREQ，BAND按支持波段表自动判定。登记后向HAMLOG、ADIF UDP等传递同一值。取消则不登记、不向外发送。TU73自动登记也相同。
