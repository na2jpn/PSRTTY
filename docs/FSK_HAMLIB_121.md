# Hamlib FSKモード確認 — 1.21

## 対象

Hamlibを使用するFSK対応のYaesu10項目・Kenwood3機種に共通で適用。
FT-991Aで実際にRTTY表示になっていてもモード確認が失敗することがあり、再試行で改善するとの報告を受けた修正。
一時的なCAT読取り失敗や切替直後の反映遅れを吸収する。
報告の根本原因が特定できたという意味ではなく、全機種で同じ症状が確認されたわけでもない。

## 手順

1. 接続・キャンセルを確認し、送受信状態を読み取る。送信中なら設定しない。不明なら再試行。
2. 現在モードを読み取る。読取り失敗は再試行。すでに指定モードなら書き換えない。
3. 別モードの場合だけrig_set_modeを1回実行。既存の帯域幅変更なし指定 -1 を維持する。
4. 読返しを再試行。取得したモードが指定と一致した場合だけ成功とする。
5. 成功後、FSK送信処理がキャンセルをもう一度確認し、PTTを入れる。

再試行間隔0.25秒、各段階最大5回。新しい呼出しを発行する確認処理全体の期限は2秒。
進行中のHamlibネイティブI/OはHamlib・機種の通信タイムアウトに従うため、実時間が厳密に2秒以下になるという保証ではない。
STOPは送信エンジンのキャンセルEventをHamlib確認処理へ渡し、待機を中断する。
接続キャンセル、切断、ハンドル変更も確認する。
GUIスレッドでは待機せず、既存の接続・送信ワーカースレッド内で処理する。
再試行のためにモード設定を連打しない。確認を省略して送信する経路は追加しない。

## エラー情報

- 送受信状態を読めない。
- 現在モードを読めない。
- モード切替指示が失敗した。
- 切替後のモードを読めない。
- 取得モードが指定と不一致。モード名と16進数の生値を付記。
- 接続なし／切断、送信中、キャンセル、確認時間超過、ドライバー例外。

試行回数、Hamlib戻り値、指定モード、取得モード、失敗段階のうち該当する情報を表示。
HamlibController.fsk_mode_errorは利用者向け8言語テキスト、fsk_mode_diagnosticは機械処理用の値。
各呼出しの開始時に情報を初期化し、過去のエラーを次の成功へ持ち越さない。
送信エラーは既存のステータス表示・トランスクリプトに渡し、設定画面の送信テストにも同じ詳細を渡す。
接続時の自動モード設定が失敗した場合も、接続エラーへ詳細を付記する。
停止操作によるキャンセルは既存の停止表示を維持する。

## 変更しない範囲

Hamlib DLLの版、モデルID、CAT接続方式は変更しない。独自CATコマンドへの切替も行わない。
ICOMのCI-V処理、AFSKのモード設定、ビットキーイングの時刻判定、1.20のメーター機能は維持。
