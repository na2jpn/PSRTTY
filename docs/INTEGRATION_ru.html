HAMLOG и интеграции

HAMLOG Ver5.48

Windows, публичный API Turbo HAMLOG/Win с 5.27c. Запустите один HAMLOG с окном ввода QSO, оба приложения с одинаковыми правами. Интеграция → HAMLOG: проверка показывает заголовок отвечающего окна. Включите перенос при записи (исходно OFF). Исходный режим только заполняет поля — сохраняйте в HAMLOG сами; другой режим запрашивает сохранение. Настройки общие для профилей. После успешного ADIF переносятся ручные и TU73 QSO, серийный номер увеличивается один раз. CALL, JST-дата/время, оба RST, частота и RTTY; SENT/RCVD в Remarks1, позывной станции в Remarks2. Обмен не угадывается как JCC/JCG, QSL/Code/GL/Name/QTH HAMLOG сохраняются.

В режиме ввода сохраните QSO в HAMLOG перед следующим. Чужой черновик защищён. Автосохранение проверяет поля перед Save. При сбое ADIF уже сохранён: проверьте HAMLOG, не добавляйте QSO повторно.

Сбой переноса

Диалог показывает причину и действие. ADIF PSRTTY уже сохранён — не добавляйте QSO снова! Прерванные операции журналируются без автоповтора. Проверьте HAMLOG, вручную внесите только недостающие или экспортируйте HAMLOG CSV из Файл. Правки/удаления HAMLOG обратно не синхронизируются.

Частота для HAMLOG усекается до 3 знаков после запятой в МГц (21.07982 → 21.079). ADIF PSRTTY хранит исходную точность.

zLog: связь через Z-Server

В настройках HAMLOG включите формат 599 и проверьте наличие RTTY=5*9. Проверьте и существующую запись RTTY.

Порядок: CALL → Enter → данные этого QSO → проверка → Save. Дата, время и RST задаются после Enter. При передаче только в поля Save нажимается вручную. При несовпадении показаны поле и оба значения; автосохранение отменяется.

  1. Запустите обычный TCP Z-Server и подключите zLog. Проверьте тест, CALL станции, обмены и время.
  2. В меню интеграции откройте zLog. Задайте сервер, порт, уникальное имя ПК, оператора и TX. На одном ПК: 127.0.0.1. UTC/JST и десятичный разделитель — как в zLog.
  3. Включите передачу новых QSO и сохраните настройки. По умолчанию связь выключена.

После сохранения ADIF новые QSO передаются при ручной записи и TU73: CALL, время, RST, обмены, RTTY, диапазон и частота. Обмены CQ WW со штатом передаются целиком; проверьте тест и множители в zLog.

Неподтверждённые QSO хранятся в var/zserver-outbox.json. При подключении проверяются ID и данные. Старые записи и QSO при выключенной связи не отправляются автоматически. Для них есть ADIF; не переносите одно QSO двумя способами. Подтверждение сервера не заменяет проверку журнала zLog. TLS/вход и обратная синхронизация правок/удалений не поддерживаются.

ADIF UDP

В Log4OM2 включите UDP Inbound, ADIF MESSAGE, с тем же портом. Пример: 127.0.0.1 (этот ПК), порт 2236. Согласуйте с приёмником.

Каждый новый QSO отправляется один раз. Правки, удаления и старый журнал не отправляются. UDP не подтверждает получение/запись; автоповтора нет. При ошибке журнал PSRTTY сохраняется.

Если частота QSO отсутствует, диалог показывает корреспондента и запрашивает МГц (7.045, 14.085, 50.303). FREQ применяется к этому QSO, BAND определяется по таблице диапазонов. HAMLOG, ADIF UDP и другие связи получают то же значение после записи. Отмена не записывает и не передаёт QSO. Правило действует и для TU73.
